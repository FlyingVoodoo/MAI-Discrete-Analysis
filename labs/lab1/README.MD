# Лабораторная работа №1: Сортировки за линейное время

## Описание задачи

Необходимо реализовать стабильную сортировку последовательности пар «ключ-значение» за линейное время. Ключом является почтовый индекс (шестизначное число), значением — строка переменной длины.

## Реализованный алгоритм

В данной работе использована **распределительная вариация сортировки подсчётом** (Counting Sort).

В отличие от классической реализации для целых чисел, где вычисляются префиксные суммы, данный алгоритм использует массив указателей на связанные списки. Индекс массива соответствует значению ключа, что обеспечивает прямой доступ к нужному «бакету» за O(1). Использование связанных списков позволяет сохранить стабильность сортировки и выполнить распределение данных за один проход по входному потоку.

## Архитектура данных и оптимизации

Программа спроектирована с использованием принципов **Data-Oriented Design** для минимизации нагрузки на подсистему памяти и процессорный кэш:

| Компонент | Описание |
|-----------|----------|
| **Пул текста** (`text_pool`) | Все входящие строки хранятся в едином непрерывном массиве символов. Это исключает фрагментацию кучи, характерную для большого количества объектов `std::string`, и обеспечивает локальность данных (Cache Locality). |
| **Пул узлов** (`pool`) | Метаданные (смещение в буфере текста, длина строки, индекс следующего элемента) хранятся в плотном массиве структур. Это позволяет оперировать индексами вместо тяжёлых указателей. |
| **Массивы `heads` и `tails`** | Хранят индексы начала и конца списков для каждого ключа. Массив `tails` необходим для добавления новых элементов в конец списка за константное время, что гарантирует стабильность алгоритма. |
| **Zero-copy подход** | В процессе сортировки сами строки не перемещаются и не копируются. Перестраиваются только логические связи (индексы `next`) между узлами. |

## Анализ сложности

| Сложность | Значение | Комментарий |
|-----------|----------|-------------|
| **Временная** | O(n + k) | n — количество записей, k — диапазон ключей (10⁶). Алгоритм содержит два последовательных этапа: чтение с распределением и линейный вывод. |
| **Пространственная** | O(n + k) | Память выделяется под массив индексов и буферы для хранения данных. Использование `reserve()` позволяет избежать накладных расходов на реаллокации. |
